1. How I Approach Software Architecture

Architecture is about managing complexity and isolating change. When building software systems, my primary objective is to separate core business rules from external dependencies such as databases, HTTP frameworks, or third-party APIs.

By establishing clear boundaries, a system remains easy to test, maintain, and upgrade over time without requiring massive code rewrites.

2. Why I Choose Clean Architecture

In projects like El Mogy Fresh and Smart Traffic Management (STMS), I implement 4-Layer Clean Architecture:

1. Domain Layer

Contains core entities, domain events, and business exceptions with zero external framework dependencies.

2. Application Layer

Defines use cases, CQRS commands/queries, DTOs, interface abstractions, and validation logic.

3. Infrastructure Layer

Implements EF Core DbContext, repository interfaces, SQL migrations, SignalR hubs, and payment gateways.

4. Presentation Layer

ASP.NET Core Web API / MVC controllers, middleware pipelines, Swagger docs, and React frontend clients.

3. CQRS: When to Use vs When Simple CRUD Is Better

CQRS (Command Query Responsibility Segregation) separates read operations from write operations. However, it introduces additional files and handlers.

When I Use CQRS (MediatR)

  • Complex business workflows involving multiple validation rules and background events.
  • Systems where read query performance requires separate DTO projections from domain entities.
  • High-concurrency emergency telemetry in Smart Traffic STMS.

When Simple CRUD Is Better

  • Basic lookup tables (e.g. medical specialties, product categories).
  • Simple admin CRUD operations without complex domain side effects.
  • Early-stage prototypes where velocity outweighs architectural abstraction.

4. Database Optimization & Security Hardening

SQL Server Indexing

In STMS and CurexMind, I implement custom non-clustered indexes on frequently filtered columns (e.g. `PatientId`, `AppointmentDate`, `VehicleStatus`) to optimize SQL execution plans and avoid full table scans.

Authentication & Webhook Security

Implementing JWT Bearer tokens with automatic refresh interceptors, 6-digit OTP email verification via Identity, and Stripe HMAC webhook signature validation to prevent tampering.
